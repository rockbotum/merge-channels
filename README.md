## Что это

Минимальный консольный проект, показывающий, как из **любого количества входных каналов** получить один выходной — паттерн **fan-in** в Go.

Каждый входной канал читается в отдельной горутине, все значения отправляются в общий канал `out`. Как только все источники исчерпаны, `out` закрывается, и цикл `range` в `main` завершается.

## Как это работает

```
ch1: A B C ─┐
ch2: D E F ─┼──►  MergeChannels(...)  ──►  merged  ──►  for val := range merged { ... }
ch3: G H I ─┘
```

1. **Источники.** Три небуферизованных канала `string`, каждый наполняется в своей горутине с задержкой (`80–150 мс`) — так видно, что слияние идёт параллельно, а не последовательно.
2. **Слияние.** `MergeChannels` принимает `...<-chan T`, создаёт `out` и спавнит по одной горутине-ридеру на каждый входной канал.
3. **Синхронизация.** `sync.WaitGroup` отслеживает завершение всех ридеров.
4. **Закрытие.** Когда счётчик доходит до нуля — вызывается `close(out)`. Это сигнал потребителю: «данных больше не будет», и `range` в `main` выходит из цикла.

```
время ↓
 A    D     B      G    C     E      F     H     I
 └────┴─────┴──────┴─────┴─────┴──────┴─────┴─────┴──► merged
      ↑        ↑                    ↑              ↑
   ch1         │                   ch1            ch2
   (100ms)   ch3 (80ms)                 (100ms)   ch2 (150ms)
```

> **Важно:** закрывать `out` должен только тот, кто им владеет. Никогда не пишите в канал извне — иначе получите `panic: send on closed channel`.

## Запуск

```bash
go run main.go
```

Требуется Go **1.18+** (для дженериков). Внешних зависимостей нет.

## Пример вывода

```

```

Значения идут в **непредсказуемом порядке** — это нормально и является главной особенностью конкурентного слияния: нет гарантии, что «первый» канал отдаст все свои значения раньше остальных. Порядок **внутри** одного канала при этом всегда сохраняется (`A → B → C`).

## API

```go
func MergeChannels[T any](channels ...<-chan T) <-chan T
```

| Параметр | Тип | Описание |
| --- | --- | --- |
| `channels` | `...<-chan T` | Любое количество входных каналов |

| Возвращает | Описание |
| --- | --- |
| `<-chan T` | Канал **только на чтение**, который закрывается после опустошения всех источников |

Ключевые детали:

- **Generics (`T any`)** — функция работает с любым типом: `string`, `int`, структуры, каналы.
- **`<-chan T` во входных данных** — принимаем каналы **только на чтение**. Компилятор запрещает запись в чужие каналы, что делает контракт самодокументируемым.
- **`<-chan T` на выходе** — потребитель физически не может закрыть или записать в канал, который ему отдали.

## Как реализовано

```go
func MergeChannels[T any](channels ...<-chan T) <-chan T {
    out := make(chan T)

    var wg sync.WaitGroup
    wg.Add(len(channels))

    for _, ch := range channels {
        ch := ch
        go func(c <-chan T) {
            defer wg.Done()
            for v := range c {
                out <- v
            }
        }(ch)
    }
    go func() {
        wg.Wait()
        close(out)
    }()
    return out
}
```

Разбор по частям:

| Решение | Зачем |
| --- | --- |
| `wg.Add(len(channels))` до старта | Счётчик известен заранее, гонок нет |
| `defer wg.Done()` | Гарантирует уменьшение счётчика, даже если в ридере появится `return` |
| `ch := ch` | Фиксирует переменную цикла для корректного захвата в горутине |
| Отдельная горутина на `wg.Wait()` | `merge` возвращает канал сразу и не блокирует вызывающий код |
| `close(out)` после `wg.Wait()` | Ровно один владелец закрывает канал — потребитель видит конец потока |

## Сложность и поведение

| Свойство | Значение |
| --- | --- |
| Тип паттерна | fan-in (многие → один) |
| Горутин на вызов | `N + 1`, где `N` — число входных каналов |
| Порядок | **не гарантирован** между каналами, гарантирован внутри одного |
| Backpressure | есть — медленный потребитель блокирует ридеры |
| Закрытие `out` | автоматическое, когда все источники исчерпаны |

## Возможные улучшения

Проект намеренно оставлен минимальным, но его легко расширить:

- **Отмена** — `context.Context`, чтобы прервать слияние досрочно, не закрывая источники.
- **Буферизация** — `make(chan T, N)` снижает переключения контекста при большом потоке.
- **Обработка ошибок** — вариант с `chan (T, error)` и завершением при первой ошибке.
- **Извлечение в пакет** — вынести `MergeChannels` в отдельный модуль и добавить тесты, бенчмарки и примеры в godoc.
